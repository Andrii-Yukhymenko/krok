# Крок / Krok

Україномовний MVP планувальника пішохідних прогулянок із встановленням як PWA.

Сайт: [Крок](https://andrii-yukhymenko.github.io/krok/).

## Розробка у WSL

Node.js >= 22.13 (у поточній WSL доступний Node 24 через nvm).

```sh
cd /home/soda/daily-step-map
nvm use 24
npm ci
npm run dev -- --host 0.0.0.0
```

Відкрити http://localhost:3000. Для GPS і PWA на телефоні потрібен HTTPS; звичайна LAN-адреса через HTTP не підходить. Вбудований браузер може не підтримувати встановлення — використовуйте Safari або Chrome.

```sh
npm test
npm run typecheck
npm run lint
npm run build
npm start -- --host 0.0.0.0
```

Service worker реєструється тільки в production. Збірка додає локальні JS/CSS у precache. Перевірка реального встановлення на iOS/Android ще потребує пристрою користувача.

## Статична збірка та GitHub Pages

`npm run build` створює готовий статичний сайт у `dist/`. Власний сервер, база даних або вхід через OpenAI не потрібні. Локальний перегляд збірки: `npm start`, потім http://localhost:4173.

Для перевірки адреси в підпапці:

```sh
APP_BASE_PATH=/krok/ npm run build
APP_BASE_PATH=/krok/ npm start
```

Відкрити http://localhost:4173/krok/. Для звичайної локальної розробки залишити `APP_BASE_PATH=/` (це значення за замовчуванням). Маніфест, іконки та service worker підтримують підпапки; кеш PWA ізольований за шляхом застосунку.

Коли будете готові до публікації:

1. Завантажити проєкт у публічний GitHub-репозиторій для використання GitHub Free.
2. У **Settings → Pages → Source** вибрати **GitHub Actions**.
3. У **Actions → Publish GitHub Pages → Run workflow** запустити публікацію.

Workflow `.github/workflows/pages.yml` запускається вручну, перевіряє тести й TypeScript, визначає шлях сайту з налаштувань Pages та публікує `dist/`. Він підтримує як адресу репозиторію, так і власний домен.

Інструкції: [GitHub Pages workflows](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages), [Vite deployment](https://vite.dev/guide/static-deploy.html#github-pages).

## Що працює

- Старт із GPS, прицілу на карті з окремим підтвердженням або координат; демонстраційний старт у Києві позначений явно.
- До точки — автоматична побудова після натискання; до 18 проміжних точок — після підтвердження.
- Ескіз пальцем/мишкою автоматично будується після відпускання. Геометрія спрощується за похибкою 25 м, а не до фіксованих 18 точок; для `trace_route` додаються зразки через приблизно 60 м. Valhalla `map_snap` зіставляє всю лінію з доріжками з допуском, без обов’язкових зупинок у кожній точці. Неповний результат або надмірний обхід відхиляється.
- Повернення тією самою геометрією: дистанція та час подвоюються.
- «Ідея»: за замовчуванням шукає реальні парки, сади, сквери, пляжі, пішохідні площі й позначені бульвари/набережні в OSM. Оцінює до трьох варіантів через одне або два місця та показує їх назви й посилання на OSM. Випадковий режим залишений окремо. Ціль не гарантується точно; маршрут може містити повторні ділянки.
- Зріст із автоматичною приблизною оцінкою кроку, денна ціль, повзунок пройдених кроків на головній сторінці та точне введення в налаштуваннях. Enter або «Готово» зберігає форму; порожні поля цілі та пройдених кроків означають нуль. Налаштування локальні; координати не зберігаються.
- Старт не встановлюється натисканням на карту: пересуньте її під приціл і натисніть «Підтвердити старт тут». Клавіатура: стрілки для пересування карти, Tab та Enter для підтвердження. Вибір точок маршруту натисканням збережений.

## Архітектура та межі MVP

React + TypeScript, Leaflet, Vite. Немає власного API чи бази даних. Компоненти карти, стан, геометрія, генерація кандидатів і підрахунок кроків працюють у браузері. Формула: `кроки = округлення(метри × 100 / довжина_кроку_см)`.

Маршрути реальними дорогами розраховує **зовнішній Valhalla**, профіль `pedestrian`. Адреса змінюється build-time змінною `NEXT_PUBLIC_ROUTING_URL`. Це публічний демонстраційний сервіс із fair-use обмеженнями, без SLA. Перед широким запуском потрібен власний інстанс або провайдер із відповідними умовами. Усі запити йдуть безпосередньо з браузера; координати бачить провайдер. Маршрут через вручну поставлені точки ділиться на запити по максимум 10 точок з однією спільною точкою на межі. Всі частини мають успішно побудуватись і з’єднатись, перш ніж показується результат. Таймаут одного запиту — 25 секунд, не більше одного запиту приблизно на секунду; пошук можна скасувати. При помилці немає підміни маршруту прямою лінією.

Карта — стандартні тайли OpenStreetMap із видимою атрибуцією. Не виконується попереднє масове завантаження або офлайн-кешування тайлів. Офлайн доступна оболонка й налаштування після успішного встановлення service worker, але для нових маршрутів і карти потрібна мережа.

Не є навігатором або крокоміром: немає фонового трекінгу, автоматичного підрахунку фактичних кроків, перевірки перекриттів або актуальних умов проходу. Точність залежить від OSM і довжини кроку. Час береться з маршрутизатора для ходьби близько 4.8 км/год.

## Наступні кроки після польового тесту

1. Калібрування кроку за реальною прогулянкою та зручніше редагування точок.
2. Подальша оцінка якості map matching на реальних ескізах у різних містах.
3. Вибір району для локального графа й маршрутизації у Web Worker/WASM, якщо потрібні повністю клієнтські обчислення.
4. Оцінка якості маршрутів через парки; додаткові переваги сходів та покриття.

## Оцінка за зростом

Довжина одного кроку оцінюється як `зріст × 0.41` з округленням до 0.1 см. Це обрана приблизна середина діапазону 0.37–0.45, який [наводить Omron](https://www.faq.healthcare.omron.co.jp/faq/show/4195?site_domain=jp), а не персонально виміряний крок. Стать, вага та вік для цієї простої моделі не потрібні. Початковий зріст 175 см потрібно замінити власним. Старе значення stride не використовується для вигадування зросту; ціль і сьогоднішні кроки зберігаються при переході.

## Мобільна карта та малювання

До 700 px карта розташована над компактною нижньою панеллю дій: «Редагувати», «Довжина», «Новий маршрут» і «Змінити старт». Натискання «Згорнути» залишає лише короткий підсумок і звільняє місце для карти; «Розгорнути» повертає кнопки, підказки та повернення попереднього маршруту. Стан панелі зберігається в localStorage після перезавантаження та побудови нових маршрутів. Повзунок довжини відкривається в цій панелі, а додаткові параметри — в окремій панелі з явною кнопкою закриття. Готовий маршрут захищений від випадкових натискань на карту; після очищення або зміни старту можна повернути попередній маршрут. Desktop зберігає бічну панель. Маркери мають власні внутрішні елементи з явним вирівнюванням; на ескізі не показуються номери технічних зразків.

На карті є перемикач «Рухати карту / Продовжити лінію», збереження попередніх штрихів та «Новий малюнок». Масштаб доступний кнопками та колесом. Два пальці в режимі малювання переводять поточний жест у масштабування; незавершений штрих скасовується, щоб не додавати випадкову лінію. На desktop пробіл між штрихами тимчасово дозволяє перетягувати карту. Фактичні touch-жести потребують повторної перевірки на телефоні.

## Джерела прогулянкових місць

`NEXT_PUBLIC_PLACES_URL` задає Overpass API (за замовчуванням overpass-api.de). Одна обмежена запитом вибірка в радіусі 0.7–4 км, максимум 120 місць і 400 доріжок; кеш у пам’яті 10 хвилин / до 8 районів. Координати старту надсилаються також цьому провайдеру. Приватні / заборонені місця виключаються за тегами. Для парків вибирається вершина доріжки всередині полігону, якщо така є у вибірці; інакше — найближча точка межі. Це евристика, не гарантія входу. Для геометрії складних relations та відсутніх тегів можливі неточності. Якщо дані недоступні, застосунок повідомляє про це, а не підмінює «паркову» прогулянку випадковою.

Пішохідний профіль Valhalla має підвищені `service_penalty`, `service_factor`, `driveway_factor` і знижений `use_living_streets`. Так службові й дворові дороги мають нижчий пріоритет. Це переваги, не абсолютна заборона: початок, кінець або відсутність іншого проходу можуть вимагати такого шляху. Брак актуальних OSM-даних не можна виправити лише коефіцієнтами. Для публічного масштабування потрібен власний провайдер даних / маршрутизації замість залежності від демонстраційних сервісів.

- [Valhalla map matching](https://valhalla.github.io/valhalla/api/map-matching/)
- [Overpass usage](https://dev.overpass-api.de/overpass-doc/en/preface/commons.html)

# Оновлення напрямку й ескізів

Лінія маршруту має стрілки й легку анімацію з підтримкою `prefers-reduced-motion`.
Зсув на 4 екранні пікселі за напрямком руху розділяє проходи туди й назад;
це лише відображення, координати й дистанція від зсуву не змінюються.

Пішохідні запити додатково віддають перевагу footway і дорогам із позначеним
тротуаром (`walkway_factor`, `sidewalk_factor`), знижуючи пріоритет alleys.
Дорога на карті може представляти й тротуар, якщо він не нанесений окремою
геометрією. Ці пріоритети не гарантують шлях виключно окремими стежками.
Параметри: https://valhalla.github.io/valhalla/api/route/api-reference/#pedestrian-costing-options

Ескіз має менш щільні проміжні зразки та більший допуск похибки.
Після зіставлення видаляються лише внутрішні симетричні відгалуження до 350 м,
що повертаються точно у ту саму вершину й не мають намальованого зразка
поблизу точки розвороту. Кільця, навмисні розвороти та ручні точки не зрізаються.
Відстань і час коригуються пропорційно видаленій геометрії; це оцінка.
Якщо зіставлення розривається, контур будується через максимум 8 основних
поворотів типу `through` без проміжних розворотів і з радіусом пошуку 100 м.
Надмірні обходи відхиляються. Довільне коло все ще може мати неоднозначне
зіставлення з мережею доріг.

# Стійкість сервісів і вибір прогулянки

Місця кешуються на пристрої (localStorage, максимум 8 областей). Радіус запиту
округлюється вгору до кілометра, максимум 4 км; повторне використання допускається
лише коли попередня область повністю покриває нову. Провайдер є частиною ключа.
Протягом доби кеш свіжий; до 7 діб його можна використати після збою з видимою
датою даних. Побудова шляху все одно потребує мережі. У довідці є очищення кешу.
Недоступне або переповнене сховище не блокує роботу в пам’яті сторінки.

Пошук місць повторюється максимум один раз після паузи від 2 секунд із дотриманням
Retry-After. Якщо сервер просить понад 30 секунд, автоматичного повтору немає.
За наявності старих придатних даних повтор пропускається. Після тимчасового збою
діє пауза щонайменше 30 секунд перед новим запитом; скасування зупиняє очікування.
Це не гарантія доступності публічного Overpass і не резервний сервер.

Діагностичний JSON завантажується кнопкою біля повідомлення в панелі маршруту.
Він містить останні 30 подій поточної сторінки: сервіс, час, тривалість, код HTTP
та тип результату. Координати, URL запитів, назви місць і геометрія не записуються.
Після перезавантаження журнал скидається. Звіт ніде автоматично не надсилається.

Серед максимум трьох реальних маршрутів «Ідея» порівнює відхилення від цілі
та частку повторно пройдених однакових сегментів геометрії незалежно від напрямку.
Оцінка: deviation + 3 × max(0, deviation − 0.15) + 0.3 × repeatRatio.
Достроковий вихід лише коли відхилення і повторення менші 5%.
Це консервативна оцінка: різне розбиття тієї самої дороги може занижувати повторення;
сусідні паралельні тротуари не об’єднуються. Частку маршруту всередині парків,
дорожні ідентифікатори й покриття ця версія ще не оцінює.

# Керування точками та свобода ескізу

У режимах однієї/кількох точок на карті є додавання, редагування та пересування
карти, побудова/повторна побудова, видалення обраної/останньої точки й очищення.
У редагуванні маркери (включно зі стартом) перетягуються з перерахунком лише
після відпускання. Для керування без перетягування можна обрати точку зі списку
та перенести до центру карти. Під час редагування немає автоматичного наближення.

Типовий ескіз тепер «Вільно»: RDP із допуском 100 м залишає до 8 головних
поворотів; звичайний pedestrian /route використовує through без проміжних
розворотів, radius 200 і rank_candidates false. «Точніше» — допуск 50 м,
radius 100. Радіус є запитаною областю пошуку кандидатів, а не гарантованою
межею відхилення всього шляху; сервер може обмежувати його власними налаштуваннями.
Для контурів сильніші пріоритети footway і штрафи service/driveway/alley.
Це не класифікація популярності або ширини пішохідних доріжок.
«За лінією» зберігає попереднє trace_route зіставлення. Зміна точності після
малювання автоматично перебудовує ескіз. Непрохідні ділянки не з’єднуються
прямими, надмірні обходи та великі зміщення кінців відхиляються.

# Обов’язкові зупинки в «Ідеї»

До 6 власних точок додаються й редагуються на карті окремо від автоматичних
місць. Порядок додавання зберігається, маршрут повертається до старту.
Перша побудова проходить лише через власні точки. Якщо вона вже близька до
цілі або перевищує її, додаткові зупинки не додаються. Інакше перевіряються
до 3 доповнень: одне/два реальні місця або випадкові точки залежно від стилю.
Додаткові точки вставляються між обов’язковими з мінімальним приростом прямої
відстані; остаточний вибір порівнює реальні пішохідні маршрути.
Невдача пошуку доповнень повертає базовий маршрут із повідомленням; помилка
самих обов’язкових точок не приховується. Відвідування допускає прив’язку до
доступної доріжки в межах 100 м від точки. Точна відповідність цілі не гарантована.
При перемиканні стилю і повторній генерації точки залишаються; зміна основного
режиму або вибір нового старту очищає їх. Перетягування старту в редакторі зберігає зупинки.

# Зміна довжини готового маршруту

Повзунок «Довжина прогулянки» є в результаті та на мобільній карті. Це окрема
бажана довжина, вона не змінює денну ціль чи вже пройдені кроки. Підбір починається
через 900 мс після останнього руху; попередній підбір скасовується. Поточний
маршрут залишається видимим до успіху, бажані й фактичні кроки показані окремо.
Зміни прив’язані до початкового маршруту сеансу повзунка, тому попереднє
скорочення не втрачає основу для наступного подовження.

Ескіз скорочується вздовж існуючої геометрії зі зміщенням фінішу; дистанція
і час пропорційні відрізаній частині. По точках зберігаються зупинки та фініш,
тож бажане скорочення може бути неможливим. Подовження ручних маршрутів
вставляє реальний пішохідний відрізок із поверненням на початкову лінію (до
3 варіантів), не малюючи неперевірених з’єднань. Повторення дороги можливі.
«Ідея» з парками перебудовується генератором для нової цілі; обов’язкові
зупинки зберігаються. Випадкова ідея без зупинок може скоротитися до проходу
туди й назад. Режим повернення враховується в цільовій та фактичній дистанції.
Помилки/неможливість підбору залишають поточний маршрут і пояснення. Повна
офлайн-перебудова та безперервна анімація геометрії не реалізовані.

### Збереження і стирачка

Профіль, старт (зокрема остання GPS-позиція), режим, зворотний шлях, точки, ескіз,
готовий маршрут і місця маршруту автоматично зберігаються в localStorage.
Положення та масштаб карти також відновлюються. Під час незавершеного запиту
залишається останній збережений стан. Виконані кроки, як і раніше, обнуляються в новий день.
Збереження не залежить від хостингу: воно окреме для кожного браузера, пристрою та origin.
Після зміни домену старі дані автоматично не переносяться; очищення даних сайту їх видаляє.

У всіх чотирьох режимах на готовому маршруті доступна кругла «Стирачка».
Затисніть мишу або проведіть пальцем по лінії: під пензлем вона зникає одразу.
Розмір пензля регулюється повзунком. Після відпускання видалена ділянка з’єднується
пішохідним шляхом з виключенням стертої дороги. Зайві відгалуження з поверненням
прибираються локально. Якщо обхід неможливий, маршрут відновлюється з поясненням;
та сама стерта дорога не приймається як успішне редагування.
Зупинки всередині стертої частини прибираються. У режимі повернення редагується
основний шлях, а повернення повторює його. Є скасування останнього руху стирачки.

У режимі стирачки один палець стирає, два пересувають і масштабують карту.
Другий палець скасовує незавершений рух стирачки. Після жесту відпустіть
обидва пальці перед новим стиранням. Середня кнопка миші пересуває карту.
